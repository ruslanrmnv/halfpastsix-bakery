# Лог решений

Каждое нетривиальное решение — строкой с обоснованием. Порядок хронологический.

## Фаза 0 — интейк

| # | Решение | Почему |
|---|---|---|
| 0.1 | Механика заказа — предзаказ с живым остатком на сегодня | Партия у пекарни физически конечна. Счётчик остатка здесь не приём давления, а факт, и он же даёт повод вернуться на сайт завтра |
| 0.2 | Страницы: Главная / Меню / Заказ / Контакты | Минимум, который держит целевое действие. «Заказ» отдельной страницей, потому что конверсия живёт внутри сайта, а не на стороннем сервисе |
| 0.3 | Отдельной страницы «О пекарне» нет, история идёт блоком на главной | Страница выбрана не была. Историю нельзя выкинуть — она снимает страх «это перепродажа промышленной выпечки», — значит она переезжает на главную |
| 0.4 | Privacy Policy и Accessibility Statement — служебные страницы из подвала | В навигацию не идут, чтобы не разбавлять четыре рабочих пункта |
| 0.5 | Cookie-баннера нет | Трекеров и сторонних скриптов не будет. Баннер без причины только режет конверсию |
| 0.6 | Заказ живёт на клиенте, финал — экран успеха с номером | Сохраняет полностью статичный экспорт и правило «ноль внешних скриптов». Разрыв честности закрывается разделом README «что заменить перед боем» |
| 0.7 | Тема и палитра решаются после фазы 1, не сейчас | Заказчик оставил на усмотрение. Решать до разбора рынка — значит решать вслепую и с высокой вероятностью попасть в ИИ-дефолт |
| 0.8 | Публикация: GitHub, затем Cloudflare Pages под свой домен | Выбор исполнителя. Статический экспорт держит оба без изменений в коде |
| 0.9 | `git init` до первого файла | Ловушка из прошлого проекта: перед крупной переделкой откатываться было некуда |
| 0.10 | Рабочие документы в `research/` — по-русски, сайт и README — по-английски | Документы читает исполнитель, сайт читает выдуманная аудитория из Портленда |

## Фаза 1 — исследование

| # | Решение | Почему |
|---|---|---|
| 1.1 | Тезис проекта: живой остаток на сегодня — главный экран, а не украшение | Из шести разобранных сайтов Портленда ни один не отвечает на вопрос «что ещё осталось прямо сейчас». У Baker & Spice 5 из 9 категорий, включая обе хлебные, отрисованы пустыми и молчат |
| 1.2 | Первый экран несёт остаток, а не фотографию | Половина разобранных главных отдана фото и каруселям. У Bakeshop карусель из восьми снимков — основное тело страницы и ноль ответов на вопросы покупателя |
| 1.3 | Пустое состояние проектируется наравне с полным и обязано называть время следующей партии | Пустая категория без объяснения — это отказ, оформленный как поломка. Замерено на живой витрине Baker & Spice |
| 1.4 | Берём реальную механику «ранняя выпечка / поздняя выпечка» | Так делит хлеб Baker & Spice — бизнес мыслит партиями, но интерфейса для этого у него нет. Занятая ниша без занявшего |
| 1.5 | Цены штучных позиций держим в `$1.50–$7.00` | Снято с живой витрины Baker & Spice 7 августа 2026. Выдуманный прайс не должен выпадать из портлендского диапазона |
| 1.6 | Комиссионный аргумент против агрегаторов в работу не берём | Цифры 15–30% приходят из блогов вендоров POS, интерес завышать. И к Square-витринам они всё равно не относятся — там процент эквайринга |

## Фаза 2 — дизайн и макет

Подробности в `design-plan.md`, здесь только сами решения.

| # | Решение | Почему |
|---|---|---|
| 2.1 | Рабочее имя — Half Past Six | Время первой партии. Поиском по Портленду не занято, полная проверка в фазе 3 |
| 2.2 | База `#EDEDE6` — холодная мука, а не кремовый `#F4F1EA` | Кремовый + сериф + терракота это ИИ-дефолт №1 и одновременно самый затёртый бейкери-штамп |
| 2.3 | Акцент — пихтовый зелёный `#1D5A3B`, тёмный | Тёмный акцент держит 4,5:1 и как заливка под белым, и как текст на светлом. Светлый не может ни того ни другого одновременно |
| 2.4 | Шрифтовая пара перевёрнута: гротеск в заголовке, сериф в теле | Все шесть разобранных пекарен делают наоборот. Разворот стоит ноль и виден сразу |
| 2.5 | Моноширинный на цифры, время и метки | Остаток и расписание выпечки в пекарне правда живут в производственном листе |
| 2.6 | Дефицит показывается зачёркиванием и приглушением, не красным | Акцент занят кнопкой. Второй сигнальный цвет разрушил бы правило одного акцента |
| 2.7 | Подпись проекта — доска: крупное число остатка и время, когда позиция кончилась | Ни один из шести сайтов не говорит, **когда** кончилось. Это и запоминается |
| 2.8 | Первый экран несёт таблицу остатков, фотографии на нём нет | Прямое следствие тезиса фазы 1 |
| 2.9 | Форма заказа — два поля | Baymard: в среднем 23,48 поля в чекауте США, почти каждый пятый бросает из-за длины. Предзаказ выпечки не требует больше имени и телефона |
| 2.10 | Логотип и текстовые ссылки-действия получают `min-height: 44px` | Замер макета поймал логотип 105×20 и ссылку 103×33. Правило уходит в токены, а не в разовую правку |
| 2.11 | Моноширинная роль снята целиком: метки и цены — курсив Newsreader, служебные заголовки и навигация — Bricolage строчными | Замечание заказчика на воротах приёмки: mono-капслук с разрядкой выглядит шаблонно и «как ИИ». Согласен — это один из самых узнаваемых приёмов генерации. Капслук и разрядка убраны вместе со шрифтом |
| 2.12 | Акцент вычищен до строго одной работы: из штампа, ссылок, выбранных состояний и фокуса `fir` убран | Ревизия по следам 2.11 нашла четыре протечки зелёного мимо кнопки. Ссылки — подчёркивание в цвете текста, выделение и фокус — `iron` |
| 2.13 | Макет прогнан через премиум-чек-лист: счёт 3/7, отчёт в `premium-audit.md`, правки идут по одной | Заказчик на воротах: «всё выглядит ужасно». Аудит подтвердил три провала замерами — доска растворялась в фоне, герой не владел экраном, страх №2 не закрыт. Вкус заменён числами |
| 2.14 | Шапка доски — тёмная планка `iron` со светлым текстом, рамка `iron`, тень-отрыв, числа до 46px | Пункт 02 аудита: тезисный элемент был свёрстан тише собственного заголовка. Тёмная планка и есть доска за прилавком — единственный тёмный якорь страницы |
| 2.15 | Десктопный сгиб владеет экраном: `min-height: calc(100vh - 79px)`, колонки центрированы; строка gone — вторая на доске | Пункты 01+03 аудита: 263px пустоты внизу и 204px под колонкой — вычислено, не показалось. На мобильном подпись проекта («gone 8:52») обязана попадать в сгиб 670px, теперь низ на 641 |
| 2.16 | Факт происхождения — в штампе первого экрана: «baking since 2018» | Пункт 05: страх №2 исследования («это не они пекут») не был закрыт ничем выше сгиба. Год из интейка; адрес — только после проверки фазы 3 |
| 2.17 | Разделительные точки штампа сидят в конце сегмента, не отдельными флекс-детьми | Находка на скриншоте 375: при переносе точка повисала в начале строки и читалась как маркер списка |
| 2.18 | Направление сменено на «горячую корку»: пшеница `#ECDDBE`, ржаная плита `#2A1A0A`, масляный акцент `#F3B229` | Ворота приёмки: заказчик снял холодное направление с диагнозом «слишком тихо и сухо», явно исключив шрифты и компоновку. Меняются палитра, масса, масштаб — тезис и структура нетронуты |
| 2.19 | Стратегия акцента перевёрнута: яркая заливка под тёмным текстом (8,8:1), не тёмная под белым | Масляный жёлтый текстом на светлом не проходит никогда — но текстом он и не работает. Правило «один акцент — одна работа» сохранено, залитая кнопка одна на страницу, проверено скриптом |
| 2.20 | Доска — целиком тёмная плита, не светлая карточка с тёмной шапкой | Смелость по диагнозу: единственная тёмная масса страницы, кремовые числа на ней — самое громкое после h1. Своя текстовая шкала на плите: `tan` 7,4:1, `tan-dim` 5,4:1 |
| 2.21 | Гарнитуры и сгиб пережили смену направления без правок | Диагноз исключил шрифты; смелость добрана весом 800 и масштабом (h1 до 72px, числа до 54px). Все замеры перегнаны: контраст 0 нарушений, тап-зоны ≥44px, gone-строка в сгибе (647 из 670), десктопный сгиб кончается на 900 |
